### 🤖 Ассистент — 2026-06-08 13:24:56

Проведен анализ структуры проекта **Tonaly_Site**. Ниже представлены результаты исследования.

### 1. Стек и логика (Backend)
*   **Стек:** FastAPI (Python 3.x), Pydantic для валидации данных.
*   **База данных:** На текущий момент используется **In-memory хранилище** (списки `offers_db`, `reports_db`). Файлы `models.py`, `database.py` и `shemas.py` созданы, но пока пусты, что указывает на этап перехода к полноценной БД (вероятно, SQLAlchemy/SQLAlchemy).
*   **Логика:** 
    *   Реализованы CRUD-операции для коммерческих предложений (Offers) и отчетов (Reports).
    *   Есть функционал загрузки изображений (`/api/reports/{report_id}/upload-photo`) с использованием `uuid` для уникальности имен файлов.
    *   Предусмотрены эндпоинты для отдачи статических HTML-документов напрямую через FastAPI (`/documents/memorandum`).

### 2. Организация Frontend
*   **Структура:** Фронтенд разделен на логические блоки: `documents/`, `offers/`, `reports/`. Каждая папка содержит свои HTML-файлы и вложенные папки `css/` со специфичными стилями (например, `documents.css`, `spravka.css`).
*   **Стилизация:** Используются CSS-переменные (`:root`) для соблюдения брендбука (цвета `tonal-primary`, `tonal-secondary`). Это облегчает поддержку единого стиля во всех типах документов.
*   **Состояние:** Файл `frontend/index.html` сейчас представляет собой простую навигационную страницу со ссылками на ключевые документы.

### 3. Связь Frontend и Backend
*   **Метод интеграции:** 
    *   **Статическая отдача:** Backend (FastAPI) настроен на отдачу `index.html` и конкретных документов через `FileResponse` и `HTMLResponse`.
    *   **API:** Взаимодействие происходит через REST API (`/api/stats`, `/api/offers` и т.д.). 
    *   **CORS:** Настроено разрешение для всех источников (`allow_origins=["*"]`), что удобно для разработки, но требует сужения в продакшене.

### 4. Оценка масштабируемости
*   **Плюсы:**
    *   Четкое разделение по типам документов (`offers`, `reports`, `documents`).
    *   Использование `Pathlib` в бэкенде делает пути кроссплатформенными (Windows-safe).
*   **Риски и рекомендации:**
    *   **Дублирование:** В каждой подпапке фронтенда (`documents/css`, `offers/css`) свои файлы стилей. При росте проекта это приведет к дублированию кода. Рекомендуется вынести общие компоненты в единую библиотеку стилей.
    *   **Отсутствие JS-фреймворка:** Сейчас это набор статических HTML-страниц. Для сложной логики (фильтрация, динамические формы) может потребоваться переход на Vue/React или использование Alpine.js/HTMX для сохранения легкости.
    *   **База данных:** Необходимо наполнить `models.py` и подключить реальную БД, так как текущие данные теряются при перезагрузке сервера.

**Итог:** Проект находится в стадии активной разработки перехода от статического прототипа к динамическому веб-приложению. Структура папок логична, но требует унификации CSS-ресурсов.
