Вот самые быстрые способы:

### 1. Через Python (уже установлен у вас)
Откройте терминал в Kodik и выполните:
```bash
python3 -m http.server 8000
```
Затем перейдите в браузере по адресу: `http://localhost:8000`. Вы увидите список файлов и сможете открыть любой HTML.

### 2. Через расширение (если нужно автообновление)
Если вы привыкли к тому, чтобы страница обновлялась сама при сохранении:
1. Установите пакет `live-server` (нужен Node.js):
   ```bash
   npm install -g live-server
   ```
2. Запустите его в корне проекта:
   ```bash
   live-server
   ```

### 3. Простой просмотр без сервера
Вы можете просто нажать правой кнопкой мыши на файл (например, `index.html`) в проводнике Kodik и выбрать **"Copy Path"** (Скопировать путь). Затем вставьте этот путь в адресную строку браузера. 
*Примечание: В этом случае пути к картинкам и стилям могут работать некорректно, если они указаны от корня сайта (`/css/...`).*

**Рекомендую первый способ (Python)** — он самый надежный и не требует установки лишнего софта.

Да, это отличная идея, и ваш текущий стек (FastAPI + Python) идеально подходит для создания такой «умной» библиотеки.

Чтобы реализовать поиск **по содержимому** (Full-Text Search), а не только по названиям, я предлагаю следующую архитектуру:

### 1. Технический стек
*   **Парсинг текста:** Библиотеки `python-docx` (для .docx), `PyMuPDF` или `pdfplumber` (для .pdf).
*   **Поисковый движок:** 
    *   *Простой вариант:* **SQLite FTS5** (встроенный модуль полнотекстового поиска).
    *   *Продвинутый вариант:* **Elasticsearch** или **Meilisearch** (очень быстрый и легкий в настройке).
*   **Интеграция с Planfix:** Использование Planfix API для автоматической прикрепления найденного файла к задаче.

### 2. Как это будет работать (План реализации)

1.  **Индексация:** Создаем скрипт, который проходит по вашим папкам, считывает текст из файлов и сохраняет его в базу данных вместе с путем к файлу.
2.  **Интерфейс поиска:** Небольшое веб-приложение (можно добавить вкладку в ваш текущий `Tonaly_Site`), где вы вводите фразу, а система выдает список документов.
3.  **Действие:** Рядом с каждым результатом поиска кнопка «Отправить в Planfix» или «Копировать путь».

### 3. Пример структуры базы данных
В `models.py` мы можем добавить таблицу:
```python
class DocumentIndex(Base):
    id = Column(Integer, primary_key=True)
    filename = Column(String)
    path = Column(String)
    content = Column(Text)  # Здесь хранится весь текст из PDF/Docx
    file_type = Column(String)
    last_modified = Column(DateTime)
```

### 4. Риски и нюансы
*   **PDF-сканы:** Если PDF — это просто картинка (скан), понадобится OCR (например, `Tesseract`), чтобы «прочитать» текст.
*   **Обновление:** Нужно настроить «наблюдателя» (watchdog), который будет переиндексировать файлы, если вы добавили новые или изменили старые.
